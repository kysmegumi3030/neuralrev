## 关键结论：1e-3 目标为何可达

可分离性测量把 5 维参数空间塌缩成：

```
        ┌─ WetCore_A(decay) ───────────────────┐
in ──┬──┤                                      ├─→ LowCut → HighCut → ×wet ─┐
     │  └─ delay(PRE-DELAY) → WetCore_B(decay) ┘                             ├─→ out
     └───────────────────────── ×dry ──────────────────────────────────────────┘
```

其中只有 **WetCore(decay)** 这一维需要靠算法结构对齐；其余（两个滤波器、
纯整数延迟、两个增益）都已闭式确定、可精确复现。

### 关键修正：两个 CUT 滤波器的拐点律（`docs/REFERENCE.md` §6.1）

**显示串上的 fc 不是 −3 dB 点。** `lowcut=0`（显示 50 Hz）实际≈**旁通**，
真实拐点 19.1 Hz；`highcut=1`（显示 10 kHz）真实 12.1 kHz。
全曲线最小二乘（7 档联立）残差 0.255 / 0.188 dB，指数两者都取精确 2。

照搬显示值时，我们的 50 Hz 高通在 20 Hz 白扣 16.5 dB（参考只扣约 4 dB）。
修正后 2k–20k 的 max 从 7.60 → 2.66 dB（**当时的读数**；经过后续两轮，
该带现在是 4.39 dB —— 见待办 1 的表，那里有为什么略升的说明）。

这个 bug 还**连带污染了 damping 的拟合**：高频本来就偏低，
拟合便把 damping 压到 800 Hz 补偿；修正拐点后重扫落点 3600 Hz。
属于「先修结构、再拟合参数」的实例。
**但 3600 也不是终点** —— 它同样是错的（用平滑谱当目标，对衰减率不敏感），
当前落点 **18400 Hz**，见下文「本轮完成」。

### 第一步：先判定旧工具还能不能用（结论：不能，两处都失效）

`tools/fit/fit_t60_scale_law.py` **整体作废**，两条理由各自独立：

1. **搜索网格方向反了。** 它的 `COARSE` 是 `[0.50 … 1.06]`，为「T60 偏长、
   需要往下压」那一代扫的（3 阶插值 + fc=18400）。插值提到 15 阶、fc 收到
   20000 之后环内损耗方向**反过来**，五档里有四档的最优点落在 1.06 **之上**
   （实测落点最高 1.2425）。旧网格根本框不住解。
   —— 这是教训 7 的第三次复发：动过结构就必须重推网格边界。
2. **目标函数用「逐带最差」是错的**，而且是原理性的。缩放**同倍**移动该档
   所有带，只能平移、不能收缩带间跨度；而逐带残差存在**符号分裂**
   （decay=0.50 的锚定 D：125 Hz +2.20、250 Hz −2.27 dB/s）。
   拿 max 当目标，会让一条**压不动的带**主导整个扫描，把真正该压的宽带项
   挤掉 —— 正是 §10.2.2 tilt shelf 那个坑。

替代品 `tools/fit/fit_t60_broadband.py`，目标改成**1 kHz 锚点带的相对误差**：
锚定口径下它**定义上**就是纯宽带项，不含形状成分（§12.9.3）。

### 落点（逐档扫描，真编译 → 真渲染 → 真测量）

| decay | 落点 | 1 kHz 前 → 后 | 逐带最差 前 → 后 |
|---|---|---|---|
| 0.20 | 1.082200 | −8.66% → **+1.19%** | 9.9 → 17.5 |
| 0.50 | 1.173400 | −13.24% → **−1.13%** | 22.3 → 17.1 |
| 0.70 | 1.242500 | −18.49% → **+0.33%** | 19.7 → 23.7 |
| 0.86 | 1.135100 | −12.73% → **−1.38%** | 26.7 → 36.1 |
| 0.94 | 1.033200 | −3.53% → **−0.32%** | 50.5 → 52.8 |

五档宽带项全部压进 **±1.4%**（原 −3.5…−18.5%）。落点沿 decay 是一条
**拱形**（1.082 → 1.173 → 1.243 → 1.135 → 1.033，0.70 最深）——
单个标量表达不了，这就是本表存在的理由，§12.6 结尾的预言成立。

### 代价：逐带最差在四档里**变差**，这仍然是对的落点

原因是几何的：某档逐带残差**跨零**时，把 1 kHz 抬平必然把已偏正的带推得
更正。0.94 档最极端 —— 1 kHz 只差 −0.3%，而 8 kHz **+52.8%**
（ref 5.533 s vs cand 8.455 s，即候选高频衰减得**太慢**）。
那 52.8% 与宽带项无关，本常数取任何值都碰不到它。

有两个预测在这一轮被实测修正，记下来：
- 我原以为 0.50 档（各带同号）逐带最差会大幅下降，实际只从 22.3 到 17.1
  —— **各带对缩放的响应并不相等**，与 §12.7「0.20 档那条带几乎不响应」同型；
- 「带间半跨度」只是**刚性平移下**的乐观下界，不是可达值
  （0.86 档半跨度算 22.6%，实际落到 36.1%）。

### 验收：净收益，无频带退化

| 量 | 重标前 | 重标后 |
|---|---|---|
| 2k–20k（唯一达标带） | 2.36 dB | **2.11 dB ✓** |
| 全档全带 max | 13.61 dB | **13.50 dB** |
| 最差锚定 \|D\|（形状项，decay=0.50） | 3.40 dB/s | 3.41 dB/s |

### 与 damping fc 的正交性是**近似**的，不是精确的

§12.9.3 说锚定让 fc（形状）与本表（宽带）正交。实测**方向对但不严格**：

（125 Hz 从 +2.20 到 +3.32）。成因是改 budget 改的是 `g_i`，每圈损耗形状

## 上一轮完成：高频尾巴过早死掉（用户验收「中频偏多、高频偏少」）

用户验收反馈的这一条，根因**不是电平错**，而是高频**衰减率**错，
而且有**两个**损耗源。完整推导见 `docs/REFERENCE.md` §7.5 / §7.6。

### 定位

先建 `tools/fit/diag_band_decay.py`：把 IR 切时间窗，逐窗算各带能量比。
曲线平坦 ⇒ 电平错（静态滤波可修）；曲线下行 ⇒ 衰减率错（必须改环内）。

| 频带 | 125 | 250 | 500 | 1k | 2k | 4k | 8k |
|---|---|---|---|---|---|---|---|
| 斜率 dB/s | +1.7 | +2.0 | +2.5 | −0.6 | **−8.3** | **−15.1** | **−13.0** |
| T60 相对 | +8.5% | −3.2% | +6.8% | −1.6% | **−23.4%** | **−49.9%** | **−55.5%** |

高频三带下行、T60 短一半 ⇒ 衰减率错。**静态滤波是错的修法**：
它按时间积分的平均量补偿，会早期补过头、晚期仍不够。

### 两个根因

1. **环内 damping 低通过狠**（`kFitDampingHz = 3600`）。它当初是用
   `fit_network.py --stage damping` 的**平滑谱**目标拟合的，而平滑谱是整段
   IR 的时间积分量，对衰减率几乎不敏感 —— 「早期偏亮 + 尾巴过暗」和
   「全程正确」能积分出很相近的频谱，所以它在错的落点上「收敛」了。

2. **`ModulatedDelay` 的线性插值**（真正被漏掉的那个）。第一轮联立拟合把
   `kFitDampingHz` 推到 **25.2 kHz —— 超过 Nyquist**（等于把 damping 关掉），
   8 kHz 的 T60 **仍差 −13.3%**。解跑出物理范围本身就是信号：环内还有
   damping 管不到的损耗。线性插值是个低通：8 kHz @48 kHz 每圈损耗
   最差（frac=0.5）**−1.25 dB**、frac 均值 **−0.80 dB**，串在环内每圈吃一次，
   8 kHz 每秒约 17 圈 ⇒ 约 **−14 dB/s** —— 比实测需要的高频超额衰减总量
   （约 −10 dB/s）还大，光这一项就已超预算。
   原注释写「调制量只有零点几个样点、可忽略」是错的：`kFitLfoDepthSamples = 11`，
   frac 会扫遍 0…1。改用 **3 阶 Lagrange**（每圈均值 −0.14 dB，好 **5.6 倍**）。

### 结果

| 量 | 改前 | 改后 |
|---|---|---|
| 最差逐带 T60 误差 | +55.9% | **+9.5%** |
| 8 kHz 逐窗斜率 | −13.01 dB/s | **+3.14 dB/s** |
| 逐带整段能量比的离散（125 Hz–8 kHz） | 4.45 dB | **0.84 dB** |
| 逐带能量比的范围 | −1.40…+3.05 dB | **−1.04…−0.20 dB** |
| `kFitDampingHz` | 3600 | **18400** |
| `kFitT60BudgetScale` | 1.13 | **1.01** |
| `kWetTrim` | 1.018411（+0.16 dB） | **0.668344（−3.50 dB）** |
| `kFitTiltShelfDb` | −4.25 | **0（低架停用）** |

### 第二阶段：斜率修好之后剩下的是**电平**

改完插值与 damping 后，逐带能量比从一条**倾斜**变成一条几乎**平的 +3 dB
宽带过量** —— 而平的偏差正是静态增益能修的那一类。
`fit_trim_tilt.py` 联立扫 `kWetTrim` × `kFitTiltShelfDb`（两者作用区在
235 Hz 以下重叠，分开扫会打架），落点 **−3.50 dB / 低架归零**。
复核后能量比全部落进 −1.04…−0.20 dB，且逐带 T60 不变（静态增益不改衰减率）。

### 低架自己归零 —— 本轮最有信息量的结果

上一轮那级低架（−4.25 dB）修的是**症状**。低频「整体偏热」大半是插值损耗的
**镜像**：高频在环内每圈被吃掉 −0.8 dB，逐带相对看就成了「低频热」。
真缺陷修好后，低架的最优落点**自己塌回 0**。

判据很干净：如果它修的是真实的网络倾斜，落点不会动。
⇒ **每次修完一个结构性缺陷，都要把所有既有的「实现补偿」常数重扫一遍**，
不能只扫与它直接相关的那几个。详见 `docs/REFERENCE.md` §10.2.2。

注意全档全带 max 只从 14.11 回到 13.55（并未低于修插值前的 13.53）：
卡住它的是 20–40 / 40–80 Hz 的模式错位（拓扑问题，待办 2），与电平项无关。
本轮真正的收益是上表的 T60 与能量比两行，即用户听到的那个问题。

关键的定性变化不是那个百分数，而是**残差符号不再单向**：改前高频单调亏空、
越晚越亏；改后各带在 ±9.4% 内正负交替 ⇒ 系统性偏差已消除。
`kFitT60BudgetScale` 从 1.13 落到 1.01 也自证了这条链 —— 它的物理含义就是
补偿环内损耗，插值损耗消掉后只剩约 1% 需要补。

### 方法论教训（第 4 条，接上一轮的三条）

4. **验收口径里必须有一个时间分辨量。** 纯频谱（哪怕是 65536 点 + 1/12 oct
   平滑）对衰减率错误可以**完全隐形**，因为它是时间积分。这个洞让高频尾巴
   快了一倍、平滑谱口径却是过关的，一直到人耳验收才抓出来。
   现在 `diag_band_decay.py` 与逐带 T60 是常规复核项。

5. **拟合解跑出物理范围时，不要收紧边界了事 —— 那是模型缺项的信号。**
   damping 的 fc 跑到超过 Nyquist，说明「只有 damping 一个高频损耗源」这个
   模型本身错了。当时若只是把上界钳到 20 kHz，就会永远停在 −13% 上，
   并把它误记为「拓扑天花板」。`fit_damping_t60.py` 的上界现在确实收到
   20 kHz，但是在**找到第二个损耗源之后**才收的。

6. **新拟合脚本的度量函数必须与既有口径逐字一致，并且要先对基线做交叉验证。**
   新写的 `fit_trim_tilt.py` 里 `smooth()` 的平滑窗写成了 `±of/2`，而
   `fit_tilt.py` / `band_report.py` 是 `±of`（宽一倍）。窗窄一半保留了更多模式
   起伏，于是**同一组常数**算出的基线是 25.46 dB，而 `band_report.py` 给
   14.11 dB。两个口径不可比 ⇒ 第一次那次扫描的**过程**直接作废（重扫）。
   抓出来靠的是「新脚本的起点值应当等于既有工具在同一常数下的读数」这条
   对账 —— 现在把它当新脚本的**必做步骤**：先跑基线、和 `band_report.py`
   对上，再开始扫。

   **注意别误读**：作废的是那次扫描的可信度，不是「−3.5 dB」这个数值。
   修好口径后重扫，落点**仍然是 −3.50 dB**（低架仍归零）—— 两次碰巧同值。
   当前 `kWetTrim = 0.668344f` 就是**修正口径后**的那次扫描给出的，不是废解。
   （这本身也说明该目标在 trim 维度上比较平坦：口径错了一倍宽，
   最优 trim 却没动 —— 与「宽带过量是一条平的偏差」一致。）

### 方法论教训 1–3（比落点本身重要；第 4、5 条见上一节）

1. **目标函数要和验收口径同形。** 初版抄了 `fit_lines_direct.py` 的
   **和式**目标，于是解拿 40–80 Hz 的退化去换别带的改善 —— 总目标降得漂亮，
   逐带口径反而变差。验收看逐带最差 ⇒ 目标就该是 **min–max**。
   改成 min–max 后，解自动停在两带交叉处，且**不再需要**额外的退化守卫
   （min–max 天然自限：任何带涨过当前最差值都会直接抬高目标）。
   中间打过两版守卫补丁，兴废经过留在 `fit_tilt.py` 的注释里。

2. **不要「猜」哪一档最差。** 守卫/目标只在它**看得见**的档位上有效。
   40–80 Hz 的最差档先被误以为是 `decay-hi`，实为 `predelay-hi`
   （13.53 vs 12.92）—— 同一个洞咬了两次。正确做法是先跑全档
   `band_report.py`、看每带的 max 落在哪一档，再决定拟合集。

3. **基线必须是「功能关闭」的状态。** 拟合脚本原先拿常数文件里的**当前值**
   当基线，重跑时基线已含上一次的落点，于是上次的退化被当成「本来就这样」
   而放过。现在强制先写 `dB = 0` 重编译再测。

顺带纠出一个**口径错误**：`band_report.py` 的 `--points` 缺省只有 5 档，
而此前所有标称「6 档最差」的数字都是它跑出来的 ⇒ 系统性偏乐观。
已全部按 6 档重测并更新上文表格。

## 更早：DECAY 衰减律与 DECAY=1.0 极限对拍

### 修掉的三个问题（按发现顺序）

1. **T60 测法有偏**。原用 EDC（反向累积能量）在 −5…−35 dB 回归。
   反向累积在窗末**必然归零**，尾巴超过窗长时出现人造膝点 ⇒ T60 系统性
   低估，且**随窗长漂移**（同一 norm=1.0：20 s 窗 47.8 s、25 s 窗 60.2 s、
   45 s 窗 526 s）。改用 **RMS 包络线性回归**（无累积、无截断偏置），
   自适应窗长 T60/40，跨度 < 25 dB 的读数只当下界。
   EDC 保留作交叉校验。

2. **8 条延迟线共用一个反馈增益**（真 DSP bug）。线长 1697…4033 差 2.4 倍
   ⇒ 每秒绕圈数差 2.4 倍 ⇒ 每秒衰减率也差 2.4 倍，尾巴成了 8 个不同
   指数的混合，**T60 根本没有定义**。改为逐线
   `g_i = 10^(−3·L_i/(T60_budget·sr))`。
   连带删掉 `feedbackFromT60()`（假设单一 g）与 `meanDelay()`
   （平均线长在此拓扑无物理意义），原处留注释防止再写回来。

3. **「参数 → T60」律在上端是无效外推**。旧的 `1/T60 = a − b·d` 在
   d=7.7145 s 穿零（参数上限却是 8.0），之后全靠钳位，d=7.70 处
   **偏长 1474%**。换成幂律距上界形式，并把 norm=1.0 的实测下界
   作为**约束**纳入（不进残差）—— 这一步是 DECAY=1.0 对拍抓出来的：
   不加约束时最优解在 d=8.0 只给 258 s，违反实测下界 2 倍。

| 上端 0.86–0.98 逐档 | −18…+1474% | **±1.9%** |
| DECAY=1.0 稳定性 | 未验 | **不发散**（45 s 净跌 15.7 dB，峰值 0.092，无 NaN） |
